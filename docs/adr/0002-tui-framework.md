# ADR-0002: TUI フレームワーク

- 状態: Accepted（S-02 の試作と実機確認を経て 2026-11-13 に確定）
- 日付: 2026-11-13

## 背景

キーボード主体で「1件ずつ判断する」TUI が必要（UI-01〜05）。通知・画面遷移・ヘルプ表示を伴う。

## 選択肢

| 案                         | 長所                                                                                | 短所                                     |
| -------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------- |
| OpenTUI + `@opentui/react` | 高機能・高速（Zig ネイティブ層）。OpenCode で本番利用実績。React の知見を流用できる | 0.x で型定義などに粗さがある             |
| OpenTUI + `@opentui/solid` | OpenCode と同じ構成で実績に近い。細粒度リアクティブで再描画が軽い                   | Solid の知見が React より少ない          |
| Ink（React for CLI）       | Node で動作し実績豊富                                                               | 大きな画面・頻繁な更新で性能が落ちやすい |

## 決定

**OpenTUI + `@opentui/react`** を採用する。

## 確定の根拠（S-02）

[S-02 の記録](../research/spikes/S-02-tui.md) より。

| 確定条件                                               | 結果                                                                                |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Current / Queue 画面のプロトタイプが無理なく書けること | ✅ Current / Queue / Help・単一/複数選択・自由入力を約200行で実装できた             |
| 外部イベントで画面が更新できること                     | ✅ spool のポーリングで、新着・キャンセルが即座に反映された                         |
| macOS で安定して動くこと                               | ✅ 実機で動作。**日本語 IME による自由入力も可能**。全角文字の罫線もずれない        |
| テストしやすいこと（追加）                             | ✅ `testRender` + `captureCharFrame` / `mockInput` で、画面を文字列として検証できる |

Linux での動作は CI 整備時（T-X01）に確認する。

## 結果・注意点

- **UI 状態は純粋な reducer にする**（S-02 の `state.ts`）。本実装では `packages/core` に置き、描画層（`apps/tui`）は表示とキー入力の割り当てだけを持つ。描画層を差し替える必要が出ても reducer はそのまま使える。
- **型定義の不具合への対処**: `<input>` の `onSubmit` が `((e: SubmitEvent) => void) & ((value: string) => void)` になっていて、`(value) => …` が型エラーになる。`onInput` で値を保持し、引数なしの `onSubmit` を使う。tsconfig の `lib` には `DOM` を入れない。
- **テストの待機**: `waitForFrame` は実時間を待たないので、タイマーで更新される画面には実時間でポーリングするヘルパーを使う。
- **ランタイム**: `@opentui/core` 0.8.4 は Node（>=26.4）にも対応し、Windows 用のビルド済みバイナリもある。ADR-0001 の「OpenTUI が Bun 前提」という理由は当てはまらなくなったが、Bun を採用するほかの理由（`bun:sqlite`、単一バイナリ化、ツールチェーンの一体化）は変わらないため、ADR-0001 は維持する。
- 0.x のため、バージョンを固定し、更新時は S-02 相当のテストで確認する。
