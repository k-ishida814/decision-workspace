# ADR-0008: サブエージェントは `claude -p` を子プロセスで動かす

- 状態: Accepted（S-03 で確認、2026-11-14）
- 日付: 2026-11-14

## 背景

Planner / Explorer / Reviewer を、親の Claude Code とは別のコンテキストで動かす必要がある（AG-01〜05）。構想資料では Claude Agent SDK を想定していた。

## 選択肢

| 案                                 | 長所                                                                                                                                                                                                                 | 短所                                                                                                            |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **`claude -p` を子プロセスで起動** | ユーザーがすでにログインしている Claude Code とプランをそのまま使える。API キー不要。`--json-schema`・`--max-budget-usd`・`--max-turns`・`--tools` で出力形式と上限を指定できる。T-206 の E2E で起動方法の実績がある | CLI の出力形式やフラグの変更に追従が必要。ユーザーの設定（Hook など）を読み込む                                 |
| Claude Agent SDK                   | 型付きの API。配布向き                                                                                                                                                                                               | 公式ドキュメントにより、第三者のツールでは原則 API キー認証（従量課金）が必要で、claude.ai のログインは使えない |
| 両方に対応                         | 選べる                                                                                                                                                                                                               | 実装と検証が二重になる                                                                                          |

## 決定

**`claude -p` を子プロセスで起動する**（2026-11-14、ユーザー判断）。起動まわりは `packages/agent-runner` に閉じ込め、将来 Agent SDK を足す場合もここだけを差し替える。

## 結果・制約

- 本ツール自身の Hook（AskUserQuestion / UserPromptSubmit）がエージェントの実行中に動かないようにする（S-03 で方法を確認）。
- エージェントには読み取り専用のツールだけを渡す（設計案 D6）。
- 費用はユーザーのプランの利用枠から消費されるため、Deep Dive・Planner・Reviewer はすべてユーザーの操作で起動する（自動では動かさない）。

## S-03 の結果（根拠）

[S-03 の記録](../research/spikes/S-03-agents.md) より。sonnet で構造化出力が 9 回中 9 回成功し、1 回あたり 10〜20 秒、$0.05〜0.16。

- 起動時は `--settings '{"disableAllHooks":true}'` と `--strict-mcp-config` を付け、本ツールの Hook と MCP が再帰的に動かないようにする（`--bare` はプランのログインを使えないため不可）。
- `--json-schema` には Zod の JSON Schema を `target: "draft-7"` で渡す。
- transcript とツール利用の記録のため、出力は `stream-json` で受ける。
