# 要件定義

> 作成日: 2026-11-13
> 起点: [concept/decision-workspace-design.md](concept/decision-workspace-design.md)
> ステータス: Draft v0.1

構想資料を、実装・検証できる粒度の要件に落とし込んだもの。要件IDはタスク（[tasks.md](tasks.md)）とテストから参照する。

## 1. 目的

LLM（Claude Code）が一度に大量の選択肢を提示する問題を解消する。意思決定を外部ストアに置き、ユーザーが1件ずつ判断できるようにし、親セッションのコンテキスト肥大化を抑える。

### 成功指標（MVP時点）

| 指標                       | 目標                                                                    |
| -------------------------- | ----------------------------------------------------------------------- |
| `AskUserQuestion` の捕捉率 | Hook有効時に100%（取りこぼしはフェイルオープンで通常UIへ）              |
| 回答までの操作回数         | 1論点あたり 2キー操作以内（選択＋確定）                                 |
| 異常時の影響               | Daemon停止・Hookタイムアウト時もClaude Codeの通常操作が継続できる       |
| 中断再開                   | 10件中5件回答した状態でClaude/Daemonを再起動しても残り5件から再開できる |

## 2. スコープ

| 区分                  | 内容                                                                                               |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| **MVP（Phase 1–2）**  | Decision Core（SQLite）、Daemon、TUI、`AskUserQuestion` のHook捕捉と回答返却、MCPでの登録・取得    |
| **次段（Phase 3–4）** | Decision Graph（依存・再検討）、Planner/Explorer/Reviewer、通常応答からの意思決定要求検出          |
| **後段（Phase 5）**   | VS Code拡張                                                                                        |
| **対象外（当面）**    | Claude Code以外のエージェント対応、マルチユーザー、リモート同期、Managed Mode の本実装（検証のみ） |

動作モードは **Compatibility Mode**（ユーザーは普段どおり Claude Code CLI を使い、Hooks/MCP で連携）をMVPとする。

## 3. 用語

| 用語     | 定義                                                                    |
| -------- | ----------------------------------------------------------------------- |
| Decision | ユーザーに判断を求める1論点。質問・選択肢・回答・根拠を持つ             |
| Option   | Decision の選択肢                                                       |
| Revision | Decision の回答履歴の1版。変更しても過去版は消さない                    |
| Session  | Decision の発生元となった Claude Code セッション                        |
| Daemon   | 状態を一元管理する常駐プロセス（Orchestrator 本体）                     |
| Client   | TUI / CLI / Hook / MCP サーバー / VS Code拡張。Daemon に IPC で接続する |

## 6. 検証済みの前提（2026-11-13 時点の公式ドキュメント）

[Claude Code Hooks](https://code.claude.com/docs/en/hooks) を確認した結果。実装時に再検証する。

- **`AskUserQuestion` は `PreToolUse` で回答できる。** 元の `questions` をそのまま返し、`answers`（質問文 → 選択ラベル、複数選択はカンマ区切り）を加えた `updatedInput` と `permissionDecision: "allow"` を返すと、プロンプトを出さずにツールが実行される。`"allow"` だけでは不十分。
- **1回の `AskUserQuestion` は1〜4問。** 本ツールでは各問を個別 Decision に分割し、すべて回答されたらまとめて返す。
- **`command` 型 Hook のデフォルトタイムアウトは600秒。** タイムアウト時は出力が破棄され、`PreToolUse` でも（`onFailure: "block"` を設定しない限り）ブロックしない → 自然にフェイルオープンになる。
- **`MessageDisplay` は表示の置換のみ。** トランスクリプトと Claude が見る内容は元のまま。コンテキスト削減には使えない（構想資料 §4 レベル2 の注意点を裏付け）。
- **`Stop` / `SubagentStop` は `last_assistant_message` を受け取れる。** トランスクリプトファイルは非同期書き込みで遅延しうるため、検出（DT-01）はこちらを使う。
- **`-p`（非対話）では `permissionDecision: "defer"` で中断し、`--resume` で再開できる。** Managed Mode 検証の足がかりになる。
- **`-p` では、permission host（`--permission-prompt-tool` の MCP ツールや Agent SDK の `canUseTool`）がないと `AskUserQuestion` 自体がツール一覧に出ない。**（T-206 で確認）permission host を渡せば提供され、PreToolUse Hook が先に回答するので host は呼ばれない。対話モードでは関係ない。
